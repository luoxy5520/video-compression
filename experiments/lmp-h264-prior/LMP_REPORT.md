# LMP 实验报告

## 问题与实验范围

本轮检验 Wan 的 final latent 与 conditional hidden 能否改善 JM 的运动或模式候选。借鉴 GNVC-VD 的时空特征复用思路，使用已有张量及 VAE 完整解码的 YUV。视频编码保持标准 H.264，本轮未运行新一轮训练、生成或盲测。[GNVC-VD](https://arxiv.org/abs/2512.05016v2)

## LMP-0 资产与基线

在 113Server 上核验 44 条历史训练、16 条历史验证样本的最终 YUV。每条样本的 VAE final Raw、step 020 Raw、历史 JM 输入 YUV 和元数据 SHA-256 一致。验证集还逐条核验了历史清单中的 prompt、seed、标签和 conditional hidden 的 SHA-256。完整输入指纹在 `audit.jsonl`。Wan 仓库提交 `9737cba`，历史模型 Wan2.1 T2V 1.3B，UniPC 20 步。冻结头使用历史 step 020 缓存的 Mode、MV 预测，训练样本上的结果属于开发诊断。

历史视频规格为 832×480、17 帧、16 fps、YUV420。B0 为 JM Fast Full Search，SearchMode=0，搜索范围 32 像素。B1 为同配置下的 EPZS，SearchMode=3。共用 QP28、Baseline/CAVLC、单参考、1I+16P、P 帧合法候选 Skip/P16×16、RDOptimization=0、关闭率控。B0 在两条暖机与重复计时样本上逐字节复现历史码流。每种配置暖机一次、正式跑三次，下表为真实编码进程的 wall time 中位数，完整计时序列在 `baseline.log`。四组输出的编码器重建、JM 和 FFmpeg 解码像素均一致。画质使用对应帧的亮度 pooled MSE 计算 PSNR。

## LMP-1 候选与判据

每个样本核验 final latent 与 step 020 clean latent 的张量值相同。final latent 为 FP32 `[16,5,60,104]`，按 2×2 latent 单元聚合成宏块特征。conditional hidden 为 FP32 `[1,7800,1536]`，根据 Wan 的 `(1,2,2)` patch 化和 time/height/width 展平顺序还原至 `[5,30,52,1536]`。VAE stride 为 `(4,8,8)`。本轮 T1 将四帧跨度上的匹配位移按恒速近似分配给四个相邻 P 帧。一个宏块网格位移映射为每帧 4 个像素，即 16 qpel。零位移和已知平移的张量测试验证了方向与比例。参考为 P 帧的前一重建帧。T0 的四帧跨度与该参考结构不匹配，未执行。T2 和 E6 为可选项，未执行。

E0 首候选取 JM 实际导出的 P16×16/list 0/ref 0 MVP，再加入零和已编码相邻或历史块运动。E1 用冻结头预测的一个候选。E2/E3 用归一化特征 9×9 位移窗口匹配。融合组按 MVP、对应先验首候选、传统其余候选、先验其余候选的顺序去重。E5 使用当前源帧和前一固定基准重建帧的低分辨率块匹配，同样和 E0 融合。边界外的特征匹配中心由匹配窗口过滤。参考外延、四分之一像素插值由项目的 H.264 MC 实现处理。中心数上限 K={1,2,4,8}，覆盖半径 r={0,2,4,8} px，按 qpel L∞ 距离计。主判据在验证前冻结为 K=2、r=2，候选覆盖至少领先 E0 五个百分点且 SAD 无明显恶化。SAD 用实际源像素和固定基准重建参考，报告每组最多两个中心的最小 SAD，未枚举局部半径内的所有搜索点。20% 实际搜索预算替代判据未测。

开发集取八条训练样本，验证集取现存固定 16 条，四个 prompt 等权。仅对同参考的合法 P16×16 块算命中与 EPE，并以全部 P 块为分母另报覆盖率。Skip 不进入 P16×16 运动指标，但仍计入全 P 块分母。各候选的提取和匹配在 CPU 运行，未发生 GPU 数据传输。离线计时未包含特征生成、线上 JM 注入或端到端开销。

## LMP-2 Mode 冻结头支路

历史合法 P 模式池只有 Skip/P16×16。M0 保留两种。M1 按冻结头的 P16 概率与 0.5 的距离排序，在最高置信的 40% 宏块只保留建议模式，其余保留两种，平均每块 1.6 个候选。M4 用真实源帧与前一固定基准重建帧的零运动亮度平均绝对差，阈值 2.8984375 仅由开发集选择。两组共享候选预算。开发与验证均按样本平均，验证的四个 prompt 各四条，因而也是 prompt 等权。

| 组 | 开发整体 | 开发 Skip | 开发 P16 | 验证整体 | 验证 Skip | 验证 P16 |
|---|---:|---:|---:|---:|---:|---:|
| M0 | 100% | 100% | 100% | 100% | 100% | 100% |
| M1 | 98.70% | 97.11% | 98.56% | 98.99% | 97.05% | 99.58% |
| M4 | 98.80% | 96.18% | 99.02% | 99.18% | 96.88% | 99.25% |

M1 的验证集最差整体覆盖为 96.13%。在降低 20% 候选预算下，M1 和 M4 均未达到本轮预设的 99% 逐类覆盖要求。未进入实际模式删减。M2/M3 依赖通过筛选的无训练时空先验，本轮未运行。固定参考的逐模式真实 RDO regret 和自适应回退成本未测。逐条结果在 `mode.jsonl`。

## Gate 与结论

| Gate | 状态 | 依据 |
|---|---|---|
| Gate 0 | pass | 冻结集合资产配对、两条基线双解码、时空 sanity check，24 条插桩码流均与各自历史基线哈希一致 |
| Gate 1 | fail | 本轮 T1、冻结头和融合的覆盖/SAD 筛选均无足够收益 |
| Gate 2 | fail | 冻结 Mode 头在减少 20% 候选时未达到逐类覆盖要求 |
| Gate 3 | not_run | 无先验支路通过筛选。S1/S2/S3/S3-fixed/S-pixel 闭环编码、回退统计、BD-Rate 和端到端加速均未执行 |
| LMP-4 | not_run | 未达启动条件 |

在本轮 17 帧、单参考 P 帧、四帧 latent 位移恒速近似和既定匹配预算下，DiT 时空特征没有提供超过 JM 原生预测与传统粗搜的候选收益。历史 JM 与 EPZS 的实测差异仅说明两种原生搜索的表现，且存在率失真差异。本轮没有测得 DiT 先验的闭环加速。若继续研究，可优先验证更高时间分辨率的既有特征能否减小相邻帧映射误差，并在匹配率失真条件下评估 JM 快速基线。
