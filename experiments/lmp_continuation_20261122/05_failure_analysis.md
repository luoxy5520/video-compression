# 执行失败与归因

首次编译通过 `CC='gcc -fcommon' OPT=3` 构建。首条原生 C0 输出 SHA-256 `f25c0365…`，历史正确 SHA 为 `b83784ab…`。这一失败重现了 11 月 21 日的编译对照。旧 `d0_timing_sanity.md` 记录了使编码选择一致所需的 `make CFLAGS=-fcommon`，它覆盖 Makefile 默认浮点选项。首次证据保存在服务器 `logs/failed-build-flags/`。恢复历史参数后重新核对两个 C0 哈希。

按历史参数重编后，sample_0000 的 28 个编码运行全部完成，C0 哈希恢复历史值。随后 FFprobe 对无时间戳的 Annex B 裸流推断出了 1200000/1，旧验证器误把该推断值作帧率。保留两套双解码日志和原始 probe 输出，改为分别检验裸流的实际解码像素与 MP4 封装的 16 fps。已获得的 28 条编码记录经编码器、配置、源及码流哈希复核后继续使用。

补充计时构建首次将变换函数改名后，旧调用点缺少部分包装函数的前置声明，编译器在 select_transform 报错。旧构建和标准错误保留在 `logs/failed-detail-build/`，修订在类型可见的头文件之后补上声明。诊断构建与主计时分开。
