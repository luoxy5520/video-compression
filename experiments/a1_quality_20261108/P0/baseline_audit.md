# A1 基线与 P0 开跑核对

1. 锁定的是扩容 hidden 非循环头。历史发布提交为 `f88ed877fb08d1c568372b0c746ae6de1a44b497`，本轮从 `b6fe1f3622f6eeeaa1c54451882a8c1dedce3801` 分支出发。历史冻结文件、Git 中的同名副本和本轮模型盘副本 SHA-256 一致。本轮从 `state.py` 加载模型，经 `baseline.py` 预导出完整状态并调用既有回放接口。
2. 状态有七个数组。模式 `uint8[16,30,52]`，qpel MV `int16[16,30,52,2]`（x/y），Y/U/V 残差 `int16[16,30,52,k,k]`（16/8/8），置信度 `float32[16,30,52,3]` 和 P16 概率 `float32[16,30,52]`。Skip 的 MV 由后端按标准派生，Skip 不消费 NPZ 内的自由残差。
3. step 20 的条件分支末块 hidden 为 `[1,7800,1536]`。逐 token 投影后按时空索引排列为 5×30×52，3D 卷积后由最后四个时间格各展开四个 P 帧。模型看到的是已缓存的全片最终生成特征，原始源画面仅在模型输出后用于评分及离线诊断。
4. 在训练视频 `sample_1000` 的第 2 个 P 帧，对六组候选验证了 Y、U、V 每像素与 JM 原生 MC 一致。更广的边界、运动和序列覆盖仍需批量核验。
5. 私有 JM 副本在既有 CAVLC 宏块层写入后读取计数器，得到该编码上下文的宏块层比特与残差比特。六组码流及适配状态加钩子前后逐字节相同。计数不含片头、NAL 开销，Skip run 和空间邻块相关。拼接候选后的实际码率需要重新编码测量。
6. 每个候选回放都从同样的 Oracle I 和同样的预测 P 前缀开始，逐值核对前缀重建。候选试算替换最后一个 P 帧的全帧 MV。重建失真包含实际变换、量化和 deblocking，空间上下文仍随候选而变。待做混合候选的整段回放。
7. 两批清单合并且按 prompt 检查无跨 split。44/16/20 条历史 train/val/test 的独立 prompt 计数见 `manifest.json`。本轮 12 条历史测试标为开发回归。一次性最终盲测尚未分配。本轮没有打开新的验证指标。
8. 旧队列在第 293 组因 `queue_score.py` 缺少 `regression` 字段退出。启动前两张 A100 空闲，旧目录与权重保持原状。
9. 锁定模型只吃 hidden 和步数。回放使用零占位输入、预导出的状态和固定 Oracle I。训练 smoke 的源帧配对残差明确标为离线诊断。日志确认完整状态覆盖和 ME 用时 0.000 s，基线没有单独的 ME 调用计数器。I 模板仅读 I 记录。
10. 验证推进门槛在 `config.yaml` 中标为待锁定。失败时回到同一个冻结 checkpoint。按视频先算 pooled P 帧 Y-PSNR，再作等权均值。报告额外列出 YUV pooled PSNR、Y-SSIM、末帧及末四帧相对最早四个 P 帧的漂移。
