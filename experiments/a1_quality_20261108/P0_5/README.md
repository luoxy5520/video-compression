# P0.5 压缩状态一致性和码率瓶颈定位

本轮沿用 P0 已锁定的门槛、44 条 train、16 条 val 和固定 Oracle I。P0 的回放和权重均原样保留。诊断从 P0 已导出的候选状态开始，最终盲测未参与。

## 联合候选

每个宏块有原生 Skip、六个 P0 P16 运动候选以及 A 原本是 P16 时的同一预测状态。Skip 在真实 A 回放中调用 JM 的 `FindSkipModeMotionVector` 与原生运动补偿，保留冻结 A 的时间参考和已编码空间邻块。探针结束恢复运动缓冲和预测缓冲。A 的码流逐字节匹配 P0，且核对所有原有 Skip 的探针值与实际 MC 一致。

局部比较使用 Y SSE 加 λ 乘候选比特。P16 SSE 取 P0 实际候选回放的去块后重建，Skip SSE 取同参考的原生零残差 MC，位于去块前。Skip 采用冻结 A 栅格下 CAVLC 连续 Skip 的合并/拆分长度。P16 的运动、系数等计数来自实测候选回放，空间上下文依候选帧而异。局部结果是候选集合的诊断性包络，整段回放单独验证所有选点。选成 Skip 时导出的 MV 和残差字段清零，回放时由 JM 根据真正的混合邻域派生运动矢量。

联合候选对同一份选择分别回放三种残差策略。

- **fixed** 使用固定 A 参考下各候选对应的残差。
- **predicted** 使用冻结 A 的预测残差。选择由离线真实源代价产生，属于诊断。
- **paired** 离线用真实源和该组自身重建链产生残差，预导出全部 P 帧状态后再严格回放。严格回放用零占位输入，码流和重建必须与离线教师逐字节相同。

三种曲线均来自完整 JM 码流与实际重建。输出状态哈希、码流哈希和三方重建检查随逐视频曲线保存。

## 码率和误差

A 为冻结基线，F 为 P0 的 λ=256 组，E 为按实际重建轨迹配对的基线 MV 全 P16 组。对 A/F 复现 P0 码流，对验证 E 复现 P0 轨迹配对码流。记录 `mb_mode`（含 Skip run）、`mb_inter`（单参考配置中的 MVD）、Y/UV 系数比特、其余宏块语法。I 帧与帧层及码流开销用实际字节减宏块语法计数。非零量化系数按原生稀疏数组统计。P 帧 Annex B 字节含 NAL 起始码。

对于同一帧和同一实际 MV，令 `MC_R=MC(重建前帧)`，`MC_S=MC(真实前帧)`。参考误差为 `MC_R−MC_S`，干净参考下的运动预测误差为 `当前源−MC_S`，理想残差为两者之差。残差误差是量化前供给的残差减理想残差，Skip 的供给残差为零。单列实际重建误差。误差相关在视频内对 `log1p(MSE)` 去均值后计算，排除第一 P 帧以免 I 初始化主导，另报逐视频相关中位数。配对 E 的量化前残差误差为零，该项相关系数无定义。

## 复现

从 113Server 的 P0 提交对应产物起跑。下面给出私有 JM 副本路径，已有副本可直接用于复跑。

```bash
p=experiments/a1_quality_20261108/P0_5
py="$HOME/Wan2.1/.venv/bin/python"
r="$HOME/a1_quality_20261108"
mkdir "$r/P0_5"
cp -a "$r/P0/jm_mb_bits" "$r/P0_5/jm"
"$py" "$p/patch_trace.py" "$r/P0_5/jm"
make -C "$r/P0_5/jm/lencod" -j8 \
  CFLAGS="-fcommon -std=gnu99 -pedantic -ffloat-store -fno-strict-aliasing -fsigned-char"
"$py" "$p/run_batch.py" --output "$r/P0_5/full"
"$py" "$p/report.py" --run "$r/P0_5/full" --output "$r/P0_5/report"
```

逐视频/逐帧比特和误差、联合候选 RD、局部包络以及 SVG 图在 `results/`。服务器保留各回放的预导出状态、码流和日志。重建及 trace 暂存于服务器共享内存，完成后清除。
