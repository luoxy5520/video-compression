# 最终 latent 的闭环质量验收

固定生成域 8 条独立测试视频，覆盖两个未见 prompt。使用最终 latent，未测试提前退出。亮度 PSNR 只统计 P 帧，逐视频取平均；码率计入整段 H.264（含 I 帧）；耗时从读取最终 latent 到生成码流，不含 DiT 和解码，完整参考沿用上一轮同批样本的独立测量。

| 路径 | P 帧 Y PSNR (dB) | 码率 (kb/s) | latent → 码流 (s) |
| --- | ---: | ---: | ---: |
| 完整 Wan VAE + 完整 JM 参考 | 41.17 | 1205.36 | 44.24 |
| 旧状态头直接回放（Oracle I） | 20.93 | 197.20 | 1.66 |
| 直接源图像头，20 生成样本 + JM 8 px | 27.18 | 2770.00 | 1.58 |
| 直接源图像头，20 生成 + 60 DAVIS + JM 8 px | 27.70 | 1848.79 | 1.58 |
| 冻结解码前缀 + 学习尾部 + JM 8 px | 34.66 | 1506.59 | 1.95 |
| **冻结解码主干 + 秩 40 投影 + JM 8 px** | **40.77** | **1287.80** | **2.66** |
| 秩 40 投影 + 旧预测模式/MV（Oracle I） | 26.28 | 1928.68 | 2.04 |
| 秩 40 投影 + JM 1 px | 40.10 | 1518.26 | 2.30 |
| 秩 40 投影 + JM 1 px + 学习 MV 候选 | 40.10 | 1514.18 | 2.34 |
| 秩 40 投影 + JM 8 px + 学习 MV 候选（补跑） | 40.77 | 1287.46 | 4.07 |

以平均亮度 PSNR 距完整参考 ≤1 dB、码率增幅 ≤10%、所有码流通过双解码作为本轮工作验收线，秩 40 混合路径通过：平均差 **0.40 dB**，单条最差 **0.85 dB**，码率 **+6.84%**。秩 40 只替换最后的因果 RGB 投影（7,779 → 7,083 参数）；四条生成域验证视频的源图像亮度 PSNR 最低 54.85 dB，独立测试均值 57.19 dB。和原生完整 VAE 加同样 8 px 局部 JM 的 40.76 dB / 1287.94 kb/s 基本等效。相对完整参考的主要耗时差来自 JM 搜索配置；没有证明投影缩减能显著加速 Wan VAE。

**独立预测模式、MV 和残差的目标仍未达到。** 同一个高保真源图像接回旧模式/MV 后只有 26.28 dB，且诊断分支还使用 Oracle I 帧。闭环重算修复了参考失配，但无法补救错误 Skip/P16 和运动决策。1 px 的额外学习候选只带来约 0.002 dB 的平均亮度提升，窄窗仍落在验收线外。8 px 的补跑仅采用了 39 个模型候选，平均亮度变化不足 0.001 dB，码率仅低 0.33 kb/s。补跑的 VAE 前向耗时与首次运行有差异，不能把整段耗时差归因于候选。88 条测试码流全部通过 JM 和 FFmpeg 解码一致性检查。纯预测回放与混合路径的码率不同，表中不是等码率比较。

源图像头的残差监督按真实 JM 参考采集：对 20 条训练和 4 条验证视频记录预测模式/MV 轨迹上的 P16 MC 像素；用同一个 MC 构造真值和预测残差。该误差项等价于对有效 P16 像素加权的源像素误差。推理时由 JM 使用当前重建参考重新计算 MC 和残差，因此不需要预存参考或测试原视频。24 条轨迹均通过双解码和 P16 像素覆盖核验。

使用 [DAVIS 2017 官方数据](https://davischallenge.org/davis2017/code.html) 自动配对 90 个视频序列（60 train / 30 val）。仅 60 条官方训练序列进入训练，未使用 DAVIS val 调参；在独立生成域上，加入 DAVIS 的直接头较等更新次数的生成域对照提升 0.52 dB。这说明该配对扩容有效，尚不足以单独消除差距。配对约 1.1 GiB，24 条轨迹产物约 1.8 GiB，直接头训练 PyTorch 峰值分配约 0.64 GiB；补测时服务器数据盘约 1.7 TiB 可用。后续应优先增加独立运动场景，针对真实闭环的 Skip/P16 和 MV 候选做学习，比较同一搜索预算下的码率和画质。

每条码流和解码结果在服务器；可机读数据见 `results/eval_*/results.json`，选秩过程见 `results/calibrated/calibration.json`。
